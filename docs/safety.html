Safety

OpenSyntax is designed to help without taking reckless actions. The model requests tools, and the runtime validates and controls those tools.

Shell-safe mode

The default permission mode is shell-safe. It allows useful commands but prompts for risky operations.

opensyntax --permission shell-safe

Permission prompts

Risky actions must be approved by the user. This includes destructive commands, large file rewrites, and explicit permission tool calls.

Destructive command protection

OpenSyntax detects patterns such as rm, sudo, git reset, git clean, force push, chmod, chown, package manager installs, recursive deletes, and Docker prune commands.

Git awareness

Git tools inspect branch, status, recent commits, and diffs. Outside a git repository, OpenSyntax reports that git features are disabled instead of failing loudly.

Minimal file edits

Patch-style editing uses exact text replacement and fails if the match is missing or ambiguous. This keeps diffs small and reviewable.

Secret protection

Provider secrets are masked in output and stored locally in encrypted form. Do not paste secrets into issues, commits, or prompts that may be logged elsewhere.

Important: Review generated diffs before committing. OpenSyntax is an assistant, not a substitute for code review.
